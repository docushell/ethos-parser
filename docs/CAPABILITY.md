# What this engine can and cannot do

**These tables describe 0.64.0-dev.1.** When the workspace version moves, this page moves with it or it
is wrong.

This is the honest inventory — the answer to *"what does ethos-parser actually do today?"* It is not
the roadmap and not a sales pitch. If something is not in the **Can** table, do not promise it.

---

## Can

Everything below runs locally, with no network and no renderer.

| Area | What works | Where |
| --- | --- | --- |
| **Classify** | Sorts a PDF into named reason codes on two axes — does it need OCR, is the layout hard — with per-page counts and three distinct exit codes. No confidence score anywhere | `classify` |
| **Extract (PDF)** | Text runs from a born-digital PDF, each with a locator back into the source bytes, and a box only where font metrics measure one — the run's pen advance over its font's ascent-to-descent envelope, not glyph outlines (contract §5.3) — from the font's own tables, or, for the standard 14, from vendored Adobe AFMs (decision #22) — and only where the run's baseline lies along one of the page's axes, in either direction, and the box lies on the page | `extract` |
| **Simple-font encodings** | `WinAnsiEncoding` in full; `MacRomanEncoding` at the 113 codes above ASCII where pdf.js and Ghostscript give one glyph name, since 2026-10-03 — the fifteen they dispute stay refused, and a run holding one is omitted and counted under `broken-font-encoding`; `StandardEncoding` in its ASCII range. A font's `/ToUnicode` overrides all three. **Since decision #43 a code the declared map leaves unmapped is read through what the font itself states** (`declared-font-codes-v3`): a `/Differences` glyph name by the Adobe Glyph List specification's rules that need no list, or an embedded TrueType program's Unicode cmap and glyph names — never the base table, never a private-use value — declared under `unmapped-codes-read-from-font`. `Q` restores the text state `q` saved, so a font set for one string no longer decodes the strings after it. **Since decision #44 a `/ToUnicode` entry that names no character** — an unpaired surrogate, or a range stepping onto one as Tesseract's `<0000> <FFFF> <0000>` does — leaves its codes unmapped instead of refusing the map (`declared-font-codes-v4`) | `extract` |
| **Standard-14 metrics** | A PDF may name `/BaseFont /Helvetica` with no `/Widths` and no `/FontDescriptor`; §9.6.2.2 permits that because a conforming reader is expected to hold the metrics. This one now does, from vendored AFMs. **10 955 previously ungroundable nodes recover**; documents declaring `font-widths-absent` went 66 → 0. Reading Helvetica's metrics for a font the document calls Helvetica is reading the document; supplying them for Arial is a substitution and stays refused | `extract`, 0.51.0–0.52.0 |
| **Extract (office)** | DOCX, XLSX, PPTX, ODT, ODS, ODP, RTF and EPUB into the same record, each addressed the way its own format addresses itself: `{part, paragraph, run}` for Word, `{part, sheet, row, column}` for a workbook, `{part, shape, paragraph, run}` for a slide, and so on | `extract` |
| **Office pages** | `pages` is always `[]` for office formats. No spreadsheet print range, slide, soft page break or RTF `\page` is ever turned into a page record | — |
| **Grounding** | Emits `ethos.grounding.v1` in both shapes: the paginated 1.0.0 shape for PDFs, and the page-less 1.1.0 shape for office documents, where each element carries its native locator instead of geometry. A DOCX quote extracted here, grounded here, and checked by the sibling verifier comes back `grounded`. **Every PDF span carries `char_start`/`char_end`** — where its text lies in its element's text, in Unicode scalars (not UTF-8 bytes, not UTF-16 units), end exclusive — so Ethos reports no `missing_char_offsets` on those artifacts. It tightens no box: a claim resolves to the same box it did. An artifact past the million-span cap carries neither spans nor offsets, and an office artifact carries neither because the page-less shape admits no spans | `ground` |
| **Grounding check** | A validator whose report is byte-identical to `ethos grounding check`'s for a valid artifact, and has the same verdict, code and path for an invalid one, whose message is its own. Measured against 15 Ethos-owned fixtures — 12 reach an artifact and are compared, and the rest fail closed rather than being skipped — all 16 committed Office documents, and 3,681 mutated artifacts. The source is read only for a valid artifact, as Ethos reads it | `grounding-check` |
| **Markdown / HTML** | Both artifacts carry an anchor map — every byte is either `source` or `syntax` — plus a census of what did not make it. Both are projected from the representation, so office documents project too. **Headings project where the document declares a level** — a PDF's tagged `/H1`..`/H6` and an EPUB's own `<h1>`..`<h6>` — **and, since decision #29, where an untagged PDF's type says so**: a line drawn at least 1.2× the document's body type is read as a heading, and since decision #38 so is a bold line at body size that the leading-gap cut sets in a block of its own — 2 to 80 characters, mostly letters, shaped as no sentence, in a document whose body is not bold. Headings are ranked by the size they are set in, then by the depth of their own section number (`2` above `2.1`), into levels 1 to 6, a bold heading below every size. Each is marked `inferred_heading` (and `inferred_heading_level` past level 1) on the representation, declared as `headings-inferred-from-type`, and projects as `#`..`######` and `<h1>`..`<h6>`, by the rule `type-size-v6`, under which a numbered bold line (`3.1.`) needs only room above it, and a bold line at the head of its text that does not stand apart — `Loan terms` over the lines it names — is a **label**: level 7, written as a bold line and never with `#` (decision #47; the heading bounds count labels apart), and as one line where its column wrapped it onto two (decision #48); where the body is a size set mostly bold — a bold statement opening the page, larger than its text — bold lines are read against the text's size instead (decision #50). It never runs where the document declares its own structure. **Measured:** on the eleven documents whose authors declare headings, the false-positive rate is **0.00%..4.61%** (worst `cfpb-home-loan-toolkit`), true headings found rose 106 → 389 against false 147 → 256, and most false ones are real headings the producer tagged `/P`; on the 200-document bench, MHS **0.4703** (band 0.0000..0.9990, median 0.4859). Decorative large glyphs — icons, drop caps on their own line — can still be read as headings, and the levels are a rank of type sizes, not the author's outline (`docs/measurements/headings/README.md`). **ODT and ODP project at the level the document declares** — `text:outline-level` on a `<text:h>`, read since 2026-09-20 under `markdown-blocks-v10` / `html-blocks-v10` — and a `<text:h>` that states **no** level projects as a paragraph rather than a guessed level 1, because the level a bare heading displays at comes from `styles.xml`, which the reader declares it did not open. ODS puts no heading on the wire at all, because a cell's block discards the flag when it closes; DOCX carries none either, because the reader keeps no `<w:pStyle>` | `markdown`, `html` |
| **Verify** | Shells out to the pinned Ethos CLI and relays its bytes verbatim. The engine does not verify anything itself | `verify` |
| **Overlay** | An annotated copy of a PDF showing what was detected, including a note counting what has **no** box to draw | `overlay` |
| **Tag** | Writes a `/Document`/`/Div` structure tree into a copy of an untagged PDF — one `/Div` per block of the reading-order cut, every element marked computed under `/A << /O /EthosParser /Derivation /Computed /Rule (gutter-columns-v4) >>`, the blocks' text wrapped in marked-content sequences inserted at token boundaries with no byte of the content re-encoded — and reads its own output back before printing it: every run, every binding and every declaration compared against the extract it wrote from. **Fills absence only**: a document that already carries a tree is refused, and so are marked-content ids without one. `extract` on the result binds every run to a computed `Document/Div` address and declares `structure-tree-engine-written`; the text record is unchanged (`docs/23-AUTO-TAGGING-SCOPE.md`) | `tag` |
| **Locate** | Reports **where** a string lies in a representation and nothing else: occurrences as node ids, character offsets into each node's own text in Unicode scalars, and that node's own geometry copied from the record. Exact on scalars — no normalization, no case folding, no whitespace folding — over each block of the reading order, so a match may join runs inside one block and **never across two**; the artifact declares what it searched. **No box is bound tighter than a run**: an occurrence carries the run's own rectangle, never a sub-run or word box ([`22-WORD-BOXES-SCOPE.md`](22-WORD-BOXES-SCOPE.md) refused those on measurement). A string that occurs nowhere is exit 0 and an empty list — there is no verdict, no score, and no exit 1 | `locate`, `mcp`, `packages/` |
| **Adapters** | MCP over stdio, a Python SDK, a Node SDK, and LangChain tools over both. Every locator is minted by the engine, handed back opaque, and re-validated on the way in. No adapter takes a geometry argument. **MCP's `markdown` tool gives a model the text to read**: the text the `markdown` command prints, from a file's `path` or a representation, after a count of what it leaves out, and no anchor map — the one Markdown that travels without its map, by decision #36, so a passage is cited through `locate` | `mcp`, `packages/` |
| **Format detection** | Decided by reading bytes at offset 0, never by file name or extension. Bytes that state no known format are refused by naming what was looked for, and nothing else. A `.csv`, a letter and a log line all get byte-identical stderr | `extract` |
| **Tables** | Row/column model with spans and cell occupancy, six named detection rules (`ruled-rects-v12`, `unruled-align-v1`, `stroke-ruled-v1`, `tagged-tables-v1`, `whitespace-tracks-v12`, `bar-labels-v1`), and a cross-check between what the geometry says and what the document's own tags say. Where the two disagree structurally, the rule refuses the grid rather than emitting it. **The ruled rule takes either of two shapes of evidence**: every implied cell covered by ink, or every row and column boundary carried end to end by the rectangle edges lying on it. Neither subsumes the other — a merged cell breaks an interior line, a rules-only grid draws no cell — so either suffices and nothing `-v3` emitted was lost. A grid accepted by its lines has a cell for each face (`ruled-rects-v7`); `-v6` emitted it with none. **Where the page's rectangles as one lattice are refused, each group of them that touch is a candidate of its own** (`ruled-rects-v8`): a footer's rule or another table no longer refuses a grid drawn whole, and a group's grid stands only where it is not one band of a shaded table, does not fold rows the page left unruled, does not run on into a wider table, and splits no column the text does not; and a group's grid whose interior lines stop at merged cells is read with them merged (`ruled-rects-v10`), never where a cell would span rows whose lines sit on its neighbours' baselines, and never from a rectangle filled white; a rectangle a group paints twice is one rectangle (`ruled-rects-v11`); and on a document that declares no author structure a group leaves out a fill painted over paint of its own colour and a rule neither of whose ends meets another rectangle (`ruled-rects-v12`). **Since decision #38 a grid is also inferred from the whitespace across a table's rows** (`whitespace-tracks-v12`, `docs/31-TABLE-TRACKS-SCOPE.md`), run page-wide and again inside each of a page's columns where one is prose, with a header set on several lines above the first row read as one row, a header cell set off its column given the column whose centre is nearest (decision #49), and two numbers set closer than an em read as two cells where that makes the line a row (decision #51), a line wider than the table re-tracking it under three rows of data and a row its wrapped cell made tall reaching past the pitch (decision #52), and a cell of several numbers a word space apart read as as many cells (decision #53): rows at a steady pitch, columns kept by centre, left or right edge so a right-aligned column of numbers is a column — a currency sign set alone joining its amount, a raised footnote mark its row, each track growing with the rows — and the content stream writing it row by row, which is what tells it from two columns of prose, waived for a grid of three rows and three columns or more with a column of numbers, no column of running text and no two flows side by side — a first column holding a short label in every row, written as one block before the values, being the table's own (decision #56). Two rows stand only complete, apart and under a header-like row; two columns need four rows and are no table beside a column of list labels or of rising page numbers. It runs last and only on a document that declares no author structure, and a cell holds only its runs' text. **Measured:** opendataloader-bench TEDS 0.1728 → 0.4254 with no table on any of the 158 documents whose ground truth holds none (0.3918 under `-v2`; `ruled-rects-v7` brings the rest). Two short rows close together can still share one row, taken as a wrap; no merged cell is inferred. **Since decision #42 a bar chart that prints its numbers is read as its table** (`bar-labels-v1`, `docs/32-CHART-LABELS-SCOPE.md`): each filled bar paired with the one number on it or just past its end and the one label at its base, series named by the legend swatch of their colour or a one-colour chart's title line, grouped and stacked bars included — a table only where the numbers agree with the bars in order and most bars of a series carry one, on a document that declares no author structure. **A value is never read off a bar's length**, so a chart that prints no numbers yields no table; line and pie charts are not read | `extract` |
| **Fabrication** | **0** across the twelve-document labelled set. Measured every run, not asserted | `table-gate-v1.md` |
| **Table accuracy** | Stated as a capability, not an average, re-measured at 0.58.0: the engine reads the tables a document **declares** (162 of 172 gold tables emitted from their tags; combined cell-slot recall **503‰**) and **detects** ruled tables where the producer drew them (geometric macro F1 **69‰**, band 0‰–590‰, median 0‰ — ten of twelve score zero). It emits nothing where neither holds | `table-gate-v1.md` |
| **Fuzzing** | Three `cargo-fuzz` targets covering the PDF entry points and the office router. One campaign ran 3.8M executions under AddressSanitizer and found nothing. Mutation testing damages every PDF fixture six ways and every office package twelve | `fuzz/` |
| **Layout regions** | Every text run says which region of its page the reading-order cut placed it in, 1-based in reading order, under `gutter-columns-v4`. **A region is a column band**: runs stacked within one column share a region however many paragraphs separate them, and the field is absent wherever the cut made no division — which is most pages. **Such a page is read top to bottom by its leading-gap blocks** (below), content-stream order kept inside each, since decision #32 (2026-09-26): on opendataloader-bench NID 0.8714 → 0.8810 with the 74 documents already read in one downward sweep unmoved, and a page set in columns the cut cannot divide is read across them where they break at one height. It is `Computed` geometry and never a role: no heading, paragraph or section is read from it | `extract` |
| **Layout blocks** | Every text run says which block of its page the cut's horizontal half placed it in, 1-based in reading order, under `gutter-columns-v4`. **A block is a stretch of text separated from its neighbours by whitespace wider than its band's own leading** — it is not a paragraph, a heading or a list item, and no role is read from it (P14). Measured on the one gate document able to carry a real paragraph label: **63.7% of real paragraph breaks at 100% precision**, never firing mid-paragraph across 719 chances. The third it misses is a ceiling rather than a shortfall — 35.1% of real breaks carry no extra leading for any gap rule to see. Absent wherever the rule declined, which includes every page of uniform body text. Its limits — whitespace only, no indent branch, recall measured on one document — are declared on every PDF artifact as `block-subdivision-leading-gap-only` | `extract` |
| **Layout units** | Since decision #38, on a document that declares no author structure, every text run says which layout unit of its page its line joined, 1-based in reading order, under `line-units-v3`: consecutive lines set no more than half a line apart, overlapping across, of one kind — body text, or an inferred heading of one level — the next opening no list marker, and since `line-units-v2` cut where a piece of text — a line's runs, cut at a gap wider than its height — follows one that ends short, and since `line-units-v3` before a body line whose first word would have fit twice over after the line above: a break its author made, not its measure. **A unit is where, never what**: it says lines read as one piece of text, not that the author wrote a paragraph. A table's runs and an `/Artifact`'s get none. Measured on ParseBench's visual-grounding pages, where layout items built from units score above line items. Markdown and HTML join a heading unit's lines, counted as `layout-unit-line-joins-v1`, so a heading set on two lines is one heading line; body text keeps its lines | `extract`, `markdown`, `html` |
| **Page furniture** | Since decision #41, on a document that declares no author structure, a run whose line is a page's running head or folio carries `furniture` — `header` or `footer` — under `margin-bands-v1`: a page's lines and tables are grouped into bands wherever half a body line or more separates them, and the first band is the header and the last the footer when it lies wholly inside the page's outer tenth, holds no table, and is not the page's only band. **Where, never what was meant**: a page title set apart at the top reads as a header too. Nothing is dropped — the runs stay in the text and in every projection. On the eight tree-stripped gate documents it flags 5,070 lines, all but four repeated page to page, and those four a form's running head and folio, its catalogue number and a cover's date. On ParseBench visual grounding moved 0.4045 -> 0.4490 | `extract` |
| **Figure regions** | Since decision #46, on a document that declares no author structure, the paths a page paints are read as figures under `figure-regions-v1` (`docs/34-FIGURE-REGIONS-SCOPE.md`): every path a fill or a stroke paints, on the page and in its forms, less its background and the panels text is set on, clustered wherever their boxes come within 3 points; a cluster of 3 paths or more covering 0.05% to 80% of the page, less than half inside a table and holding no line of prose is a `FigureRecord` in the representation's `figures` array — a box and the rule id, `Computed`. **Where, never what**: a region claims no run and names no caption, and neither projection writes it. Not read: a row of icons along one rule (one region), the text inside a figure, and a raster image with the paths drawn over it. On ParseBench visual grounding moved 0.4708 -> 0.4824 | `extract` |
| **Bold and italic** | A run carries `bold` or `italic` where the font that drew it declares the style — a `/FontWeight` of 600 or more, the ForceBold or Italic flag, or `Bold`, `Black`, `Heavy`, `Semibold`, `Demibold`, `Italic` or `Oblique` in its `/BaseFont` — and since `page-observations-v4` where the TrueType or OpenType program it embeds states one (`OS/2` weight class 600 or more, or `head`'s macStyle where it has no `OS/2`; the italic or oblique bit), and a run painted fill-then-stroke (rendering mode 2 or 6) is bold; the Markdown and HTML projections write `**`/`*` and `<strong>`/`<em>`, never inside a heading or a table cell (decision #38). Nothing is read from stem widths or outlines, nor from a bare CFF or Type 1 program. Nothing is estimated from stem widths or outlines. PDF only; the office readers do not set it yet. On ParseBench semantic formatting moved 0.097 -> 0.349 | `extract`, `markdown`, `html` |
| **Superscripts and subscripts** | A run carries `script` — `superscript` or `subscript` — where it is set short (six characters or fewer), at most nine tenths the em of a run beside it on another baseline, and raised or lowered off that baseline by a tenth to half that run's em: a footnote mark, an ordinal's letters, a formula's index. The Markdown and HTML projections write `<sup>` and `<sub>`, inside any emphasis and never inside a heading or a table cell (decision #40). Read from positions and rendered ems alone; the text is the document's. PDF only. On ParseBench semantic formatting moved 0.3623 -> 0.4060; content faithfulness 0.6633 -> 0.6613 and opendataloader-bench NID 0.8857 -> 0.8835, because both score footnote marks as plain text — a cost the owner accepted | `extract`, `markdown`, `html` |
| **Form XObjects** | A `Do` naming a `/Form` runs the form's content stream where it stands — under its `/Matrix`, with its own resources, each time it is drawn, nested to a depth of eight and never into itself — so its text runs and images are the page's, and `classify` counts its text. A run drawn inside one names its font by the resource path that reaches it (`Xf1/F1`). A form drawing itself, one nested past eight and one whose `/Matrix` is not six numbers are not entered and are counted as `form-xobjects-not-descended`; an `/MCID` a form opens binds nothing and is counted as `form-xobject-mcids-not-bound`; `tag` refuses a document showing text through one. **Measured** (decision #37, [`30-FORM-XOBJECTS-SCOPE.md`](30-FORM-XOBJECTS-SCOPE.md) §13): over 2,308 documents no run lost and no new refusal, 566 documents gain 82,285 runs; ParseBench content faithfulness 0.6478 -> 0.6612 | `extract`, `classify` |
| **Determinism** | Two runs over one document produce identical bytes, in every format | CI |

## Cannot

Some of these are *not yet*. Others are refusals no version reverses. The middle column says which.

| Claim | Kind | Why |
| --- | --- | --- |
| **"v1 is complete"** | done | Closed on decision #18: v1 states the table capability and the band rather than a single macro. Fabrication is 0, the method is pinned in `table-gate-v1.md`, and the geometric chase stays parked |
| **OCR, or a scan read as extracted text** | not yet — v4 | Recognition is a different class of derivation and needs its own trust ladder. An OCR fingerprint must be provably incomparable with a born-digital parse before that lane can exist **Until then, a scan can be read through an OCR pass outside the engine** (decision #45): rasterize its pages (`gs -sDEVICE=png16m -r300`), read each with Tesseract into a PDF (`tesseract page.png page pdf`), and extract that PDF — the text arrives as invisible text, declared under `invisible-render-mode-text`, and the artifact is the OCR'd file's, never the scan's. `docs/measurements/parsebench/ethos_bench.py` runs exactly this under `ETHOS_BENCH_OCR=1`. |
| **CSV** | refusal, with named reopening conditions | A CSV parse would not fabricate content — every character would be real. Exactly one field would be false: the record would claim the file *is* a CSV when nobody measured that, and there is nowhere in the record to mark a field as asserted rather than measured. Reopens if either the record gains that distinction, or someone builds a format predicate with a measured false-positive rate |
| **Converting office files to PDF to get pages** | refusal | It invents pagination. A DOCX has no pages, and a page on a Word citation measures the printer rather than the document. Not as a fallback, not behind a flag |
| **An EPUB's `page-list` as pagination** | refusal | It names pages of a *print* edition. A page record is a page with a width and a height; a publisher's label about someone else's paper has no geometry to validate against |
| **A paragraph boundary on an untagged page** | not yet | A `region` opens only at a **vertical** gutter, so it separates columns and not paragraphs. The nearest thing is a `block` (Layout blocks, above): it opens at a whitespace gap wider than its band's leading, which catches 63.7% of real paragraph breaks on the one labelled document and misses every paragraph set without extra space. The engine never says a block is a paragraph. Paragraph structure comes from the tag tree or not at all; neither `region` nor `block` stands in for it. Since decision #38 a `layout_unit` groups an undeclared page's lines by their spacing (Layout units, above), and it is not a paragraph either: no role is read from it |
| **A Tagged PDF, or a tag another reader can tell from an author's** | refusal, declared | What `tag` writes is engine-local by decision #23: the derivation lives in an attribute object only this engine reads, so a reader that does not read `/A` sees author structure, and `structure-tree-engine-written` on the artifact is the only other statement. No `/MarkInfo` is written and content outside the sequences is not marked `/Artifact`, so the file is not a Tagged PDF and claims no conformance; a block is where text lies, never what it is, so no `/P`, heading, list or table is ever written (`docs/23-AUTO-TAGGING-SCOPE.md` §9) |
| **Right-to-left text in logical order** | **yes, beside the drawn order — decision #54, `right-to-left-lines-v1`** | A producer whose layout engine has resolved bidi writes Hebrew or Arabic in visual order, so a run's `text` is the logical word reversed — `rtl-hebrew-visual-order` is the fixture. The run keeps that `text`, its `char_codes` and its `synthesized` as drawn (`Extracted`), and since decision #54 a line whose right-to-left letters outnumber its left-to-right ones is also **read right to left**: its glyphs taken where the page draws them, each code's characters kept whole (a lam-alef ligature's two letters stay in their order), the Unicode Bidirectional Algorithm (`unicode-bidi`) giving the order they are read in, numbers and Latin inside left to right. Each run takes its place in reading order where its first glyph is read and carries its `reading` (`Computed`); Markdown, HTML, grounding and `locate` read it, so a quote typed in logical order is found and a quote copied out of a viewer still matches `text`. Measured on ParseBench: Arabic content 0.29 → 0.89, Hebrew 0.31 → 0.86. **Not read**: a line mostly left to right (an English line quoting a Hebrew word), a line where a run's glyphs would not be read together, a run of several right-to-left glyphs whose pen states no direction — `right-to-left-not-reordered` counts those runs. A mirrored glyph (a bracket) keeps the character its font maps it to, so a producer mapping the mirrored glyph to its own shape reads the opposite bracket |
| **A folded, normalised or fuzzy `locate` match** | refusal in `-v1`, with named reopening conditions | `locate-scalar-exact-v1` is exact on Unicode scalars. A case-insensitive, NFC-normalised or whitespace-folded search is a **`-v2` rule with its own id**, never a flag on this one: a flag would make two answers under one rule id, and the id is what makes two artifacts comparable. The same holds for a match crossing a block boundary, and for searching a table cell's concatenated text — the next `-v2` candidate (`docs/26-LOCATE-SCOPE.md` §4.1, §12) |
| **A word box, or any box tighter than a run** | refusal, on measurement | `locate` echoes the run's own rectangle for an occurrence inside it. Sub-run boxes were refused on measurement in `docs/22-WORD-BOXES-SCOPE.md` §7, and an occurrence is not a place to reintroduce them |
| **A confidence score, grade, or `is_good` field** | refusal | Enforced by a CI grep that fails the build |
| **A verdict about a claim or a citation** | refusal, permanent | The engine owns extraction and grounding. Verification belongs to the verifier, and a second verification implementation is exactly the failure this project is arranged to prevent |
| **Any AGPL dependency, or a JVM** | refusal | `cargo deny` enforces the licence rule, and CI proves the proof by flipping a crate to AGPL and requiring rejection |
| **A benchmark table comparing this to other parsers** | refusal | Headline numbers in this space are publisher-owned. The same tool has scored 0.000 and 0.693 on tables under two publishers, differing only by invocation flags |
| **Page rasters / screenshots** | not yet | Needs a PDF renderer, and this build depends on no C++ stack and no AGPL code by decision |
| **Table evidence a `/Form` XObject paints** | not yet, and **measured** | A form's text runs and images are read as the page's since decision #37; the rectangles and lines it paints are not offered to the table rules. The ruled rule builds one lattice from every rectangle on a page, and a header tab drawn by a form broke two tables on `opendataloader-bench` (TEDS 0.1728 -> 0.1343) while ParseBench's table score did not move. A table whose rules a form draws is not detected from them ([`30-FORM-XOBJECTS-SCOPE.md`](30-FORM-XOBJECTS-SCOPE.md) §8) |
| **A PDF's `/ActualText`, `/Alt` and `/E`** | not yet | A run's text is the glyphs the page draws. The document's own replacement text, alternate description or abbreviation expansion, on a marked-content sequence or a structure element, is counted as `actual-text-not-read` since 2026-09-27 and not read: reading `/ActualText` would replace drawn text, which needs a derivation decision of its own |
| **The document's own metadata — a PDF `/Info` dictionary or `/Metadata` XMP stream, OOXML `docProps`, ODF `meta.xml`, an EPUB's `<dc:>` elements** | not yet | Every format this engine reads carries author-declared metadata and no reader opens it for its values. An EPUB's package document is read for its **spine** and walked past for its `<dc:title>`; an ODF `meta.xml` is already inside the reader's unread-entry count, but a count names a part and never what it holds. So no title, author, producer, creation date or keyword reaches an artifact, and no node addresses one. Declared as `document-metadata-not-read` on every representation and every classification, all nine formats — the two artifact shapes that carry an assurance block. The Markdown, HTML and `locate` artifacts carry none, so they say nothing about it either way |
| **Office embedded images, audio and video** | not yet | Counted and declared by every reader, never decoded. A media part has no text, no address a citation could bind to, and no geometry |
| **RTF tables, pictures, embedded objects and fields** | not yet | `\cell` and `\row` are recorded as a paragraph terminator, which is a fact the file states, and never as a table, because no detector ran |
| **Decoding an RTF `\'hh` byte above 0x7F without a Windows-1252 declaration** | refusal | Its meaning depends on a code page. Since 2026-09-27 a byte the stream declares Windows-1252 (`\ansicpg1252`), in a font of the ANSI character set, is read as that character — TextEdit writes every accented character so. Any other is counted instead: emitting a Latin-1 character for it would be mojibake dressed up as success |
| **EPUB stylesheets, scripts, media overlays and `alt` text** | not yet | No stylesheet is read, so text hidden by `display: none` is still in the record and generated text is not. Attributes are never read as text |
| **A line break between two CJK characters in an EPUB** | not yet | CSS removes it; this reader turns it into a space. The correct rule needs a computed `white-space` value and the scripts on both sides |
| **`.odg` drawings and ODF templates** | not yet | Format detection is exact rather than prefixed, so a drawing is refused by name rather than producing a plausible artifact for a format nobody decided to support |
| **Speaker notes, slide masters and layouts as slide text** | refusal | Notes are a second stream and a master's text belongs to every slide. Splicing either in would be a silent *addition* to the evidence, which is worse than a silent drop because a consumer cannot tell it apart from the real thing. Both are counted instead |
| **Text in ODP shapes other than frames and custom shapes** | not yet | Those two are what a presentation writes for text. The set is read off the specification and kept narrow, because no corpus of real `.odp` files was available to measure which others matter |

## The rule underneath both tables

Everything the engine could not do is **stated** — as a named limitation, a typed absence, or a
counted bucket. A gap is never presented as a success. When something moves from **Cannot** to
**Can**, it moves with a measurement, not with a sentence.
